Una API Key es como una llave digital personal o tarjeta de hotel: cuando tu código en Python se comunica con los servidores de Groq en la nube, esta llave le indica al servidor quién está haciendo la solicitud para otorgarle acceso a los chips de aceleración LPU sin costo.

¿Qué hacemos? Instalamos la librería oficial de Python de Groq (groq), leemos nuestra clave secreta e inicializamos el objeto client para comunicarnos con los modelos Llama.

from google.colab import userdata

# Resolución dinámica de modelos activos en Groq
def obtener_modelo(client, preferido, alternativo):
    try:
        activos = [m.id for m in client.models.list().data]
        return preferido if preferido in activos else alternativo
    except Exception:
        return alternativo

modelo_ligero = obtener_modelo(client, "llama-3.1-8b-instant", "openai/gpt-oss-20b")
modelo_grande = obtener_modelo(client, "llama-3.3-70b-versatile", "openai/gpt-oss-120b")
modelo_qwen   = obtener_modelo(client, "qwen/qwen3.6-27b", "qwen/qwen3.6-27b")

def limpiar_respuesta(texto):
    if not texto: return ""
    return re.sub(r"<think>.*?</think>", "", texto, flags=re.DOTALL).strip()

print("Cliente de Groq inicializado correctamente.")

Q&A y Diagnóstico de Errores: AuthenticationError 401 & SecretNotFoundError 1 diagnóstico

El error SecretNotFoundError indica que el nombre asignado en Colab Secrets no coincide exactamente con GROQ_API_KEY (sensible a mayúsculas) o que no se activó el interruptor "Notebook access". El error AuthenticationError 401 ocurre cuando la API Key ha sido revocada o copiada con espacios en blanco adicionales.

¿Qué es exactamente un Token? La analogía de las piezas de Lego

Los modelos de lenguaje no ven letras ni palabras enteras como los humanos. Ven tokens, que son piezas o fragmentos de palabras (como sílabas con números asignados). Por ejemplo, la palabra "computadora" puede dividirse en 2 o 3 tokens: ["compu", "tado", "ra"]. El modelo calcula probabilidades matemáticas sobre estos números.

Q&A: ¿Por qué no contamos caracteres o palabras en lugar de tokens? 1 pregunta resuelta

Porque la arquitectura Transformer procesa matrices de vectores donde cada token representa una posición en la ventana de contexto. Las APIs de inferencia y la memoria VRAM están delimitadas por tokens máximos (ej: 8,192 o 128,000 tokens), no por longitud de texto en caracteres.

¿Qué significa "Zero-Shot"?

Zero-Shot significa hacerle una pregunta al modelo "en frío", directamente, sin darle ejemplos previos de cómo queremos que responda (sin ejemplos = cero tiros/intentos). Si le diéramos 2 ejemplos de preguntas con sus respuestas ideales antes de hacer la nuestra, se llamaría Few-Shot.

Paso 3 · Celda 3

PRIMERA LLAMADA A LLAMA (ZERO-SHOT)

¿Qué estamos haciendo, por qué y para qué en este Paso 3?

¿Qué hacemos? Enviamos nuestro prompt a través de internet hacia los chips de Groq, solicitando que el modelo ligero genere una respuesta en modo Chat Completions.
¿Por qué? Para poner a prueba la capacidad de comprensión del modelo de lenguaje y ver en la práctica cómo redacta texto coherente en español.
¿Para qué sirve en los siguientes pasos? El resultado de esta llamada nos devuelve un objeto completo llamado response, el cual analizaremos en el Paso 4 para revisar cuántos tokens consumió y cuánto costó.

  • Estructura de Mensajes: Enviamos una lista con un diccionario que especifica el rol del emisor: "role": "user" (el usuario humano).
  • Límite max_tokens=500: Es el freno de seguridad que le dice al modelo: "puedes generar como máximo 500 tokens de respuesta, no te extiendas indefinidamente".
03_primera_llamada_zeroshot.py 
# Enviar el prompt a Llama en Groq y mostrar la respuesta generada

response = client.chat.completions.create(
    model=modelo_ligero,
    messages=[{"role": "user", "content": prompt}],
    max_tokens=500
)

print(response.choices[0].message.content)

Q&A: ¿Qué significa choices[0]? ¿Puede haber más de una elección? 1 pregunta resuelta

Sí. Si pasas el parámetro n=3 a la API, el modelo generará 3 respuestas alternativas independientes para el mismo prompt. Por defecto n=1, por lo que siempre se accede al elemento en el índice 0.

¿Cómo se cobra y mide el consumo de un LLM en la industria?

Las empresas de IA no cobran por hora ni por megabytes de internet: cobran por millón de tokens. Además, los tokens que tú envías (entrada / prompt) suelen costar la mitad que los tokens que el modelo redacta (salida / completion) porque generar texto requiere mucho más cálculo que leerlo.

Paso 4 · Celdas 4 y 5

INSPECCIÓN DE LA RESPUESTA COMPLETA & CUÁNTOS TOKENS CONSUMIÓ EL PROMPT

¿Qué estamos haciendo, por qué y para qué en este Paso 4?

¿Qué hacemos? Abrimos el paquete completo devuelto por la API (response.usage) y extraemos la telemetría exacta: cuántos tokens tuvo la pregunta, cuántos tuvo la respuesta y la suma total.
¿Por qué? Para auditar y entender el costo real y la eficiencia del modelo. En proyectos reales, no monitorear esto puede generar costos imprevistos.
¿Para qué sirve en los siguientes pasos? Este conteo de tokens será uno de los indicadores clave que guardaremos en nuestros diccionarios de resultados en el Challenge.

  • prompt_tokens: Los tokens consumidos al procesar tu pregunta de entrada.
  • completion_tokens: Los tokens consumidos al redactar la respuesta generada.
  • total_tokens: La suma matemática de ambos, que determina el consumo de cuota por minuto.

Q&A: ¿Cómo calcular el costo financiero en USD de una llamada? 1 fórmula explicada

Multiplicando los prompt_tokens por la tarifa de entrada por millón (ej: $0.05 / 1M en Llama 3.1 8B) y los completion_tokens por la tarifa de salida (ej: $0.08 / 1M), sumando ambos resultados.

¿Por qué importa tanto la latencia de un modelo?

Si un usuario le pregunta algo a un chatbot y este tarda 5 segundos en contestar, la experiencia se siente lenta y frustrante. En cambio, si responde en menos de 1 segundo, la conversación se siente fluida y natural. En ingeniería, medimos esto con un cronómetro digital en milisegundos.

Paso 5 · Celda 6

MIDIENDO LA LATENCIA DE INFERENCIA

¿Qué estamos haciendo, por qué y para qué en este Paso 5?

¿Qué hacemos? Usamos la librería time de Python para tomar la hora exacta justo antes de enviar la pregunta y la hora exacta cuando llega la respuesta, calculando la resta (duracion = final - inicio).
¿Por qué? Para conocer científicamente la velocidad del hardware LPU de Groq y tener una métrica cuantitativa.
¿Para qué sirve en los siguientes pasos? Nos permitirá comparar numéricamente si un modelo más grande tarda más tiempo que un modelo ligero en el Paso 6.

  • Time-to-First-Token (TTFT): El tiempo que transcurre hasta que el primer carácter aparece en pantalla.
  • Throughput (Velocidad): Cuántos tokens por segundo es capaz de generar la red neuronal (en Groq supera los 500 tokens/segundo).
05_medicion_latencia.py 
# Medir el tiempo de respuesta de Llama para el mismo prompt

import time

inicio = time.time()
response_tiempo = client.chat.completions.create(
    model=modelo_ligero,
    messages=[{"role": "user", "content": prompt}],
    max_tokens=500
)
duracion = time.time() - inicio

print(f"Tiempo de respuesta: {duracion:.2f} segundos")

Q&A: ¿Por qué la primera llamada puede tardar más que las subsecuentes? 1 causa técnica

Por el establecimiento de la sesión TLS/TCP y la inicialización del socket HTTPS (fase de "Warm-up"). Las llamadas siguientes reutilizan el canal de conexión con menor latencia.

La analogía del vehículo: ¿Motoneta o Camión de Carga?

Un modelo ligero (20B / 8B) es como una motoneta ágil: consume poquísima gasolina, acelera al instante y es ideal para entregar paquetes pequeños (preguntas frecuentes). Un modelo masivo (120B / 70B) es como un camión de carga pesada: tarda más en arrancar y consume más combustible, pero es indispensable para mover cargas gigantescas (cálculos matemáticos complejos o lógica densa).

¿Qué es un "Model Router" y por qué ahorra hasta 80% de dinero?

Un Model Router es como un recepcionista inteligente: cuando entra una pregunta fácil (como "¿a qué hora abren?"), se la pasa a un modelo pequeño y barato (Llama 8B/20B) que responde en 0.7 segundos. #!/usr/bin/env python3
"""
Módulo: IA Aplicada con Modelos Abiertos
Challenge: Comparador de Modelos Llama
Alumno: Ing. Jesús Javier Hernández Olvera
"""

import os, re, sys, time, pprint
from pathlib import Path
from dotenv import load_dotenv
from groq import Groq

# 1. Cargar variables de entorno desde .env
env_path = Path(__file__).parent / ".env"
load_dotenv(dotenv_path=env_path)

API_KEY = os.environ.get("GROQ_API_KEY")
if not API_KEY:
    print("Error: Se requiere GROQ_API_KEY en .env")
    sys.exit(1)

client = Groq(api_key=API_KEY)

# Modelos configurados para evaluación
MODELO_LIGERO = "openai/gpt-oss-20b"
MODELO_GRANDE = "openai/gpt-oss-120b"
MODELO_QWEN   = "qwen/qwen3.6-27b"

def limpiar_respuesta(texto):
    if not texto: return ""
    return re.sub(r"<think>.*?</think>", "", texto, flags=re.DOTALL).strip()

# 2. Definición de las 3 Preguntas de Negocio
preguntas = [
    "¿Cómo puedo restablecer mi contraseña olvidada en el portal web institucional?",
    "¿Cuál es el horario de atención y los canales oficiales para soporte técnico?",
    "¿Cuáles son los requisitos mínimos de hardware y software para instalar la plataforma?"
]

# 3. Función de inferencia comparativa
def consultar_pregunta(pregunta: str, num: int):
    print(f"\nProcesando Pregunta {num} en los 3 modelos...")

    # Modelo Ligero (20B)
    t0 = time.time()
    r_lig = client.chat.completions.create(model=MODELO_LIGERO, messages=[{"role":"user", "content":pregunta}], max_tokens=600)
    dt_lig = time.time() - t0

    # Modelo Masivo (120B)
    t1 = time.time()
    r_grd = client.chat.completions.create(model=MODELO_GRANDE, messages=[{"role":"user", "content":pregunta}], max_tokens=600)
    dt_grd = time.time() - t1

    # Modelo Qwen (27B)
    t2 = time.time()
    r_qwn = client.chat.completions.create(model=MODELO_QWEN, messages=[{"role":"user", "content":pregunta}], max_tokens=600)
    dt_qwn = time.time() - t2

    return {
        "pregunta": pregunta,
        "modelo": MODELO_LIGERO,
        "respuesta": limpiar_respuesta(r_lig.choices[0].message.content),
        "tiempo_segundos": round(dt_lig, 2),
        "tokens_prompt": r_lig.usage.prompt_tokens,
        "tokens_respuesta": r_lig.usage.completion_tokens,
        "tokens_totales": r_lig.usage.total_tokens,
        "modelo_grande": MODELO_GRANDE,
        "respuesta_grande": limpiar_respuesta(r_grd.choices[0].message.content),
        "tiempo_grande": round(dt_grd, 2),
        "tokens_grande": r_grd.usage.total_tokens,
        "modelo_qwen": MODELO_QWEN,
        "respuesta_qwen": limpiar_respuesta(r_qwn.choices[0].message.content),
        "tiempo_qwen": round(dt_qwn, 2),
        "tokens_qwen": r_qwn.usage.total_tokens
    }

# 4. Ejecución y consolidación
resultado_1 = consultar_pregunta(preguntas[0], 1)
resultado_2 = consultar_pregunta(preguntas[1], 2)
resultado_3 = consultar_pregunta(preguntas[2], 3)

resultados = [resultado_1, resultado_2, resultado_3]

# 5. Despliegue de Resultados
print("\n" + "=" * 120)
print("TABLA COMPARATIVA CONSOLIDADA (SALIDA DEL CHALLENGE 1):")
print("=" * 120)
for i, r in enumerate(resultados, 1):
    print(f"{i}. {r['pregunta'][:35]}... | Ligero: {r['tiempo_segundos']}s ({r['tokens_totales']} tok) | Grande: {r['tiempo_grande']}s ({r['tokens_grande']} tok) | Qwen: {r['tiempo_qwen']}s ({r['tokens_qwen']} tok)")
print("=" * 120)
