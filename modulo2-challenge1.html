Fundamentos de Integración

Arquitectura del Ciclo Bidireccional de WhatsApp Cloud API

La integración con WhatsApp Cloud API (Graph API v21.0) opera mediante una separación estricta de responsabilidades: Meta aloja el cluster de telecomunicaciones y entrega los mensajes mediante webhooks HTTP asíncronos hacia tu endpoint, mientras que tu backend responde invocando la API de envío de mensajes con credenciales Bearer.

Criptografía Perimetral Verificación de Integridad HMAC-SHA256 de Payloads
$$\text{Signature}_{valid} \iff \text{HMAC-SHA256}(K_{app\_secret}, M_{raw\_body}) = H_{header}$$
Desglose Exhaustivo de Variables y Mecanismos de Seguridad ▼
  • $K_{app\_secret}$: Secreto de la aplicación (App Secret) generado en la consola de Meta for Developers. Nunca viaja por la red.
  • $M_{raw\_body}$: Cuerpo crudo en bytes de la petición HTTP POST entrante. Debe verificarse antes de cualquier parseo JSON.
  • $H_{header}$: Firma hexadecimal provista por Meta en el encabezado x-hub-signature-256 (con prefijo sha256=).
  • Garantía: Previene suplantación de identidad (Spoofing) y asegura que cada evento provenga matemáticamente de Meta.

Fase 1: Handshake de Verificación GET (Apretón de Manos)

Cuando registras tu URL en el panel de Meta, sus servidores envían una petición GET /webhook con tres parámetros de consulta (query params): hub.mode=subscribe, hub.challenge=<número_aleatorio> y hub.verify_token=<tu_token>. Tu servidor debe validar que el token coincida exactamente con tu secreto local y devolver el valor crudo de hub.challenge en texto plano con código 200 OK.

Fase 2: Ingesta de Eventos POST & Deduplicación por WAMID

Cada vez que un cliente envía un mensaje o cambia su estado de lectura, Meta despacha un payload JSON complejo en POST /webhook. Para garantizar un comportamiento idempotente ante reintentos de red de Meta, almacenamos los identificadores únicos wamid en un caché LRU en memoria. Si un wamid ya fue procesado en los últimos 10 minutos, se responde de inmediato 200 OK sin ejecutar lógica adicional.

Implementación de Producción

Script Completo: Servidor FastAPI con Webhooks y Deduplicación

Copia o descarga el código fuente homologado para ejecutar tu gateway localmente con FastAPI y Uvicorn: 

from fastapi import FastAPI, Request, HTTPException, Response, Query
from collections import OrderedDict
import time

app = FastAPI(title="WhatsApp Webhook Gateway", version="1.0.0")

VERIFY_TOKEN = "mi_token_secreto_de_verificacion_2026"
PROCESSED_WAMIDS = OrderedDict()
MAX_CACHE_SIZE = 1000

def es_mensaje_duplicado(wamid: str) -> bool:
    if not wamid:
        return False
    if wamid in PROCESSED_WAMIDS:
        return True
    PROCESSED_WAMIDS[wamid] = time.time()
    if len(PROCESSED_WAMIDS) > MAX_CACHE_SIZE:
        PROCESSED_WAMIDS.popitem(last=False)
    return False

@app.get("/webhook")
def verify_meta_webhook(
    hub_mode: str = Query(None, alias="hub.mode"),
    hub_verify_token: str = Query(None, alias="hub.verify_token"),
    hub_challenge: str = Query(None, alias="hub.challenge")
):
    if hub_mode == "subscribe" and hub_verify_token == VERIFY_TOKEN:
        return Response(content=hub_challenge, media_type="text/plain")
    raise HTTPException(status_code=403, detail="Token de verificacion invalido.")

@app.post("/webhook")
async def receive_meta_event(request: Request):
    payload = await request.json()
    entry = payload.get("entry", [])[0]
    changes = entry.get("changes", [])[0]
    value = changes.get("value", {})
    messages = value.get("messages", [])
    
    if not messages:
        return {"status": "event_acknowledged_no_message"}
        
    msg = messages[0]
    wamid = msg.get("id")
    remitente = msg.get("from")
    texto = msg.get("text", {}).get("body", "")
    
    if es_mensaje_duplicado(wamid):
        return {"status": "duplicate_skipped", "wamid": wamid}
        
    # Procesar mensaje de forma asincrona
    return {"status": "message_received", "from": remitente, "text": texto, "wamid": wamid}
Resolución de Dudas Frecuentes

Preguntas Frecuentes: Webhooks & Meta Cloud API

¿Por qué Meta devuelve error de verificación al configurar mi URL en ngrok?

Asegúrate de que tu servidor responda al parámetro hub.challenge en texto plano puro (text/plain) y con código HTTP 200, no encapsulado en un JSON ni con comillas dobles.

¿Por qué recibo el mismo mensaje múltiples veces en producción?

Si tu endpoint tarda más de 3 segundos en responder 200 OK a Meta, su infraestructura asume un fallo transitorio de red y reintenta la entrega. Debes responder 200 OK de inmediato y procesar la inferencia en segundo plano (BackgroundTasks), deduplicando por wamid.
