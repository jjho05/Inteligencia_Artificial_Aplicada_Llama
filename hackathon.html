Estrategia de Proyecto · Filtro de Problemas

1. ¿Cómo Concebir tu Proyecto? Qué SÍ Resuelve un LLM y Qué NO

El error más costoso en ingeniería de Inteligencia Artificial es elegir un problema que no se adapta a la naturaleza probabilística de los modelos de lenguaje. Antes de escribir código, filtre su idea a través de este marco de decisión técnica:

Casos Óptimos Problemas que un LLM + RAG Resuelve con Excelencia:
  • Asistente Normativo / Políticas: Consultas sobre estatutos, reglamentos o manuales de procedimientos donde el usuario requiere citas fácticas y cero alucinación.
  • Clasificación & Extracción Estructurada: Convertir correos, quejas o mensajes libres en objetos JSON con tipado estricto (Pydantic).
  • Tutoría Socrática Adaptativa: Explicar conceptos técnicos paso a paso, formulando preguntas de comprobación al alumno en lugar de dar toda la solución.
  • Enrutamiento de Intenciones (Router): Filtrar en milisegundos si un mensaje es un saludo o si requiere consultar la base vectorial.
Antipatrones Problemas que NO Debes Intentar Resolver con un LLM Puro:
  • Cálculos Matemáticos / Contabilidad Exacta: Los LLMs son redes probabilísticas de predicción de tokens, no motores aritméticos. Para cálculos use Python tradicional.
  • Base de Datos Transaccional (CRUD): Un LLM no almacena registros de forma determinista con propiedades ACID. Use PostgreSQL / SQLite.
  • Predicciones Numéricas de Series de Tiempo: Para predecir precios de acciones o demanda cuantitativa use modelos de regresión (XGBoost, ARIMA).

Analogía Sencilla para Entender RAG + LLM: El Escritor Inteligente y el Bibliotecario Veloz

Imagina que estás contratando a dos personas para atender la oficina de atención a clientes:

  • El Escritor (El LLM / Llama): Es una persona sumamente elocuente, amable y rápida redactando en español perfecto, pero no se sabe de memoria los reglamentos internos de tu empresa. Si le pides una política específica sin darle el manual, intentará adivinarla para no quedar mal (Alucinación).
  • El Bibliotecario (El Motor RAG): Es un asistente veloz que tiene organizado todo el archivo de tu empresa. En menos de 20 milisegundos busca entre cientos de páginas y le entrega al Escritor exactamente el párrafo del reglamento que resuelve la duda del cliente.
  • El Resultado (El Sistema Completo): El Escritor toma el fragmento que le trajo el Bibliotecario, lo lee con atención y le redacta al cliente una respuesta perfecta, empática y 100% verídica citando el artículo correspondiente.
Definición del Alcance Mínimo Viable (MVP) para el Hackathon:

Un proyecto de excelencia para este módulo no requiere miles de páginas ni meses de entrenamiento. Consiste en tres entregables claros y funcionales: (1) Un archivo con 10 a 15 fragmentos de texto limpios de su temática, (2) Un motor RAG en Python con búsqueda cosenoidal calibrada, y (3) Un endpoint HTTP en FastAPI que reciba preguntas y devuelva respuestas fundamentadas.

Marco Comparativo · Estrategia de Selección Técnica

2. Taxonomía de Técnicas: ¿Cuándo Usar Prompting, RAG o Fine-Tuning?

Una de las preguntas más frecuentes de los participantes es: "¿Debo reentrenar el modelo (Fine-Tuning) o basta con hacer RAG?". La respuesta depende de si busca actualizar **conocimiento fáctico** o modificar el **estilo, formato y comportamiento**:

Técnica Caso de Uso Ideal Actualización de Datos Costo Computacional Riesgo de Alucinación
Prompting Directo Tareas genéricas, redacción, traducción rápida. Estática (lo que el modelo aprendió en pre-entrenamiento). Nulo (0 GPU horas). Alto en datos especializados.
RAG (Retrieval-Augmented Generation) Consultas sobre políticas, catálogos, estatutos o documentación privada. Instantánea (editar archivos de texto). Muy Bajo (solo encodeo de embeddings). Mínimo (anclado en contexto recuperado).
LoRA / QLoRA (Fine-Tuning PEFT) Enseñar formatos JSON estrictos, jerga técnica específica o tono conversacional propio. Requiere reentrenar adaptadores con nuevo dataset. Medio (10 - 30 min en GPU T4). Medio si se pregunta fuera del dataset.
Arquitectura Híbrida (Router + RAG + LoRA) Sistemas completos de grado industrial para empresas. Instantánea para datos + Robusta en formato. Balanceado para Google Colab. Cero alucinaciones con umbral cosenoidal.
Regla de Oro para el Hackathon: Si su proyecto requiere responder preguntas sobre normas, productos o trámites que pueden cambiar con el tiempo, utilice RAG como base. Si además necesita que la salida sea un JSON sin texto adicional, combine RAG con validación Pydantic o un adaptador LoRA.
Ingeniería de Prompts · Control Fáctico

3. Anatomía de un System Prompt de Grado Industrial

Un System Prompt profesional no es una simple frase como "Eres un asistente amable". Debe estructurarse con **delimitadores semánticos**, **restricciones negativas explícitas** y **mecanismos de admisión de ignorancia**:

Prompt Débil (Principiante) Alta Alucinación 
Eres el asistente de la tienda TechStore. Responde las preguntas de los clientes usando la información de nuestras políticas. Sé muy amable y ayuda en todo lo que puedas.

Fallas: No delimita qué parte es contexto, no prohíbe inventar respuestas cuando falta información y no define formato de salida.

Prompt Industrial (Meta Llama Standard) Cero Alucinación 
<|begin_of_text|><|start_header_id|>system<|end_header_id|>
Eres el Asistente Oficial de TechStore. Tu objetivo es resolver dudas de clientes basándote EXCLUSIVAMENTE en el fragmento provisto en [CONTEXTO].

### REGLAS OPERATIVAS ESTRICTAS:
1. Responde de forma concisa, profesional y empática en idioma español.
2. Cita textualmente el número de artículo o cláusula cuando esté disponible en el contexto.
3. Si la respuesta NO se encuentra de forma explícita en el [CONTEXTO], responde EXACTAMENTE:
   "No cuento con información oficial sobre este tema en el reglamento vigente. Por favor contacte a soporte@techstore.com".
4. NUNCA asumas, inventes precios, plazos o condiciones que no figuren en el texto.

[CONTEXTO]
{contexto_recuperado_rag}
[/CONTEXTO]<|eot_id|>
<|start_header_id|>user<|end_header_id|>
{pregunta_usuario}<|eot_id|>
<|start_header_id|>assistant<|end_header_id|>
Data Engineering · Preparación de Textos

4. Ingeniería de Datos: Recolección, Extracción y Sanitización

El 80% del éxito de un sistema RAG reside en la **calidad de los datos de entrada**. A continuación se presenta el pipeline formal de extracción y limpieza para ingerir PDFs, páginas web o archivos de texto:

data_cleaner.py 
import re

def sanitizar_texto(texto_crudo: str) -> str:
    """Elimina encabezados repetitivos, saltos de linea huerfanos y caracteres no validos."""
    # 1. Normalizar saltos de linea y tabulaciones
    t = texto_crudo.replace("\r\n", "\n").replace("\t", " ")
    
    # 2. Eliminar numeros de pagina y cabeceras OCR comunes (ej. "Pagina 12 de 50")
    t = re.sub(r"P[aá]gina\s+\d+\s+de\s+\d+", "", t, flags=re.IGNORECASE)
    
    # 3. Eliminar multiples espacios en blanco consecutivos
    t = re.sub(r"[ ]{2,}", " ", t)
    
    # 4. Eliminar lineas vacias redundantes
    t = re.sub(r"\n{3,}", "\n\n", t)
    
    return t.strip()
Segmentación Documental · Prevención de Pérdida de Contexto

5. Estrategias Avanzadas de Chunking y el Fenómeno "Lost in the Middle"

Segmentar textos arbitrariamente por número de caracteres puede cortar oraciones clave a la mitad. Para el Hackathon se recomienda implementar **Chunking Recursivo por Separadores Semánticos**:

Jerarquía de Separadores Semánticos:

  1. \n\n → División por párrafos completos (preserva unidades temáticas).
  2. \n → División por líneas o cláusulas.
  3. . → División por oraciones completas.
  4. → División por palabras (último recurso).
Efecto "Lost in the Middle" (Liu et al., 2023): Los LLMs procesan con mayor precisión la información ubicada al principio y al final del prompt. Al inyectar $k$ fragmentos recuperados en el System Prompt, ordene los documentos más relevantes con mayor puntaje de confianza en las posiciones extremas.
Álgebra Lineal Aplicada · Embeddings

6. Matemáticas de la Búsqueda Vectorial & Similitud Coseno

Cada texto se proyecta como un vector denso $\mathbf{v} \in \mathbb{R}^{d}$ (donde $d=384$ para MiniLM). La similitud semántica entre la pregunta del usuario $\mathbf{q}$ y el documento $\mathbf{d}$ se calcula mediante el coseno del ángulo entre ambos vectores:

$$\text{Similitud Coseno}(\mathbf{q}, \mathbf{d}) = \cos(\theta) = \frac{\mathbf{q} \cdot \mathbf{d}}{\|\mathbf{q}\|_2 \|\mathbf{d}\|_2} = \frac{\sum_{i=1}^{d} q_i d_i}{\sqrt{\sum_{i=1}^{d} q_i^2} \sqrt{\sum_{i=1}^{d} d_i^2}}$$

Al activar normalize_embeddings=True en SentenceTransformer, los vectores quedan proyectados sobre la hiperesfera unitaria ($\|\mathbf{q}\|_2 = 1, \|\mathbf{d}\|_2 = 1$), lo que reduce la similitud a un simple producto punto matricial ($\mathbf{q} \cdot \mathbf{d}$) ejecutable en microsegundos mediante NumPy o FAISS.

¿Cómo Entender un Embedding sin Saber Álgebra Lineal? La Analogía del Mapa de la Ciudad

Imagina que a cada idea o concepto del mundo le asignamos una dirección geográfica (coordenadas de latitud y longitud):

  • Si el usuario escribe "coche" y en tu documento dice "automóvil", no comparten las mismas letras, pero en el mapa semántico viven exactamente en la misma cuadra. La distancia entre ellos es casi cero.
  • En cambio, la palabra "lechuga" vive en el extremo opuesto de la ciudad. Su distancia es enorme y el ángulo entre sus vectores es amplio ($\cos(\theta) \approx 0.05$).
  • El modelo de embeddings no memoriza letras; ubica cada oración en un mapa de 384 dimensiones. La Similitud Coseno simplemente mide qué tan cerca están dos ideas en ese mapa conceptual.

8. Estrategia de Reranking: Eliminando Falsos Positivos

En documentos con vocabulario técnico similar, la búsqueda por embeddings bi-encoder puede recuperar fragmentos que comparten palabras clave pero no la semántica exacta. Un **Reranker Cross-Encoder** evalúa la pregunta y el fragmento de forma conjunta para reordenar los resultados con precisión milimétrica:

Pipeline de 2 Etapas:

1. Recuperación Densa (Etapa 1): Extrae los $top\_k = 10$ fragmentos más cercanos mediante Bi-Encoder ($< 10\text{ ms}$).
2. Reordenamiento Cross-Encoder (Etapa 2): Califica cada par $(Pregunta, Fragmento)$ y selecciona los 2 mejores con confianza máxima.

Estándares de Calidad · Buenas Prácticas vs. Antipatrones

9. Lo que SÍ Sirve vs. Lo que NO Sirve en un Proyecto de IA

Consulte esta tabla comparativa de decisiones de ingeniería para evitar los errores más comunes de principiantes:

Dimensión Técnica Lo que SÍ Sirve (Buena Práctica) Lo que NO Sirve (Antipatrón)
Estructura del Prompt Usar delimitadores explícitos (ej. [CONTEXTO]...[/CONTEXTO]) y roles directos. Escribir un párrafo largo desordenado esperando que el modelo adivine qué parte es instrucción y qué parte es dato.
Control de Veracidad Instruir textualmente: "Si la respuesta no está en el contexto, di 'No cuento con información oficial'." Dejar el modelo sin restricción, permitiendo que invente leyes, precios o políticas inexistentes.
Temperatura de Muestreo Fijar temperature = 0.1 - 0.2 para consultas factuales, legales o de soporte técnico. Usar temperature = 0.8 - 1.0 provocando respuestas cambiantes y alucinaciones en datos críticos.
Salidas Tipadas (JSON) Validar la respuesta con modelos Pydantic en FastAPI antes de retornarla. Asumir que el LLM siempre devolverá JSON perfecto sin agregar texto conversacional no estructurado.
Seguridad de Claves Cargar tokens y claves desde variables de entorno con os.getenv("HF_TOKEN"). Escribir tokens de Hugging Face o Groq en texto plano dentro del código o repositorios públicos.

Arquitectura de Software · Patrón en Cuatro Capas

12. Arquitectura de Software del Starter Kit

Para garantizar escalabilidad, bajo acoplamiento y facilidad de mantenimiento, el sistema se organiza en cuatro capas de procesamiento independientes:

CAPA 1 · ROUTING

Enrutador Semántico (router.py)

Analiza la intención del usuario. Si es un saludo o consulta trivial, responde de inmediato. Si contiene palabras clave temáticas, deriva a RAG o al adaptador LoRA.

CAPA 2 · CONOCIMIENTO

Motor Vectorial (rag_engine.py)

Transforma documentos en vectores de 384 dimensiones. Realiza búsqueda por producto punto normalizado y extrae los fragmentos más relevantes ($\ge 0.40$).

CAPA 3 · INFERENCIA & LORA

Generación Condicionada (Llama 3 / LoRA)

El modelo Meta Llama 3 sintetiza la respuesta final basándose estrictamente en el contexto recuperado, o activa matrices LoRA ($r=8$) para formatear JSON estructurado.

CAPA 4 · INTEROPERABILIDAD

API RESTful (api_server.py)

Servidor FastAPI asíncrono con CORS habilitado. Expone el endpoint /v1/chat para comunicación HTTP con validación mediante esquemas Pydantic.

13. Glosario Técnico y Analogías Intuitivas

Para que cualquier participante o jurado comprenda los fundamentos técnicos del sistema sin confusiones conceptuales:

RAG vs LLM Puro Analogía 1

La Analogía del Escritor y el Bibliotecario: Un LLM puro es como un escritor talentoso pero con memoria imperfecta: si le preguntas por las políticas de tu empresa, intentará adivinar o inventar (alucinación). RAG le pone al lado un bibliotecario veloz que le entrega exactamente la página oficial abierta; así, el escritor solo redacta la respuesta sustentada en ese papel.

Embeddings & Similitud Coseno Analogía 2

La Analogía del Mapa de la Ciudad: Un embedding convierte una frase en coordenadas GPS de 384 dimensiones. Dos frases como "¿Cómo pido mi dinero de vuelta?" y "Política de reembolsos y garantías" quedan ubicadas en la misma calle. La similitud coseno calcula la distancia en línea recta entre ambas coordenadas.

LoRA (PEFT) Analogía 3

La Analogía del Post-it en la Enciclopedia: Si tienes una enciclopedia médica de 20 tomos (el modelo base de 1B u 8B parámetros), no la reescribes para aprender un formato JSON nuevo; simplemente pegas una pequeña nota adhesiva (Post-it) en la portada con las reglas del formato. Eso es LoRA: congela el 99.9% de los pesos y solo entrena dos matrices pequeñas ($A$ y $B$).

Módulo 1 rag_engine.py · Motor Vectorial y Búsqueda por Similitud Coseno

Indexa textos documentales, calcula incrustaciones en $\mathbb{R}^{384}$ y recupera contexto relevante con umbral de filtrado:

rag_engine.py 
import numpy as np
from sentence_transformers import SentenceTransformer

class VectorRAGEngine:
    """Motor de busqueda vectorial para recuperacion de contexto factico."""
    def __init__(self, model_name="all-MiniLM-L6-v2"):
        self.embedder = SentenceTransformer(model_name)
        self.documentos = []
        self.embeddings = None

    def index_documents(self, docs: list[str]):
        """Calcula embeddings con normalizacion L2 para producto punto equivalente a coseno."""
        self.documentos = docs
        self.embeddings = self.embedder.encode(docs, normalize_embeddings=True)

    def search(self, pregunta: str, top_k=2, umbral_minimo=0.40):
        """Recupera los fragmentos que superan el umbral de confianza cosenoidal."""
        q_emb = self.embedder.encode([pregunta], normalize_embeddings=True)[0]
        similitudes = np.dot(self.embeddings, q_emb)
        mejores_indices = np.argsort(similitudes)[::-1][:top_k]
        
        resultados = []
        for idx in mejores_indices:
            if similitudes[idx] >= umbral_minimo:
                resultados.append({"texto": self.documentos[idx], "confianza": float(similitudes[idx])})
        return resultados

# Inserte los textos de su caso de estudio institucional:
mis_documentos = [
    "Las solicitudes de reembolso aplican en un plazo maximo de 30 dias naturales con ticket.",
    "Los envios estandar demoran de 2 a 4 dias habiles en cobertura nacional.",
    "Los equipos cuentan con 12 meses de garantia de fabrica ante defectos tecnicos."
]

rag = VectorRAGEngine()
rag.index_documents(mis_documentos)

class ModelRouter:
    """Clasifica la intencion de la consulta para derivar al pipeline correspondiente."""
    def __init__(self):
        self.palabras_clave_rag = ["politica", "reembolso", "devolucion", "garantia", "envio", "costo"]
        self.palabras_clave_lora = ["json", "esquema", "ticket", "ficha"]

    def route(self, mensaje_usuario: str) -> str:
        texto = mensaje_usuario.lower()
        if any(p in texto for p in self.palabras_clave_rag):
            return "RAG_PIPELINE"
        if any(p in texto for p in self.palabras_clave_lora):
            return "LORA_ADAPTER"
        return "FAST_LLM"

import json

lora_config = LoraConfig(
    r=8,
    lora_alpha=16,

class LoRAStructuredAdapter:
    """Adaptador especializado en transformar incidencias en objetos JSON tipados."""
    def __init__(self, pipeline_ref):
        self.pipe = pipeline_ref

    def extract_structured_json(self, texto_usuario: str) -> dict:
        prompt = (
            "<|system|>\nEres un clasificador JSON. Responde con un objeto JSON valido con: "
            "'categoria', 'severidad', 'resumen' y 'accion_sugerida'.\n"
            f"<|user|>\nClasifica: {texto_usuario}\n<|assistant|>\n{{"
        )
        salida = self.pipe(prompt, max_new_tokens=120)[0]["generated_text"]
        json_raw = "{" + salida.split("<|assistant|>\n{")[-1].strip()
        try:
            return json.loads(json_raw)
        except Exception:
            return {"categoria": "soporte_general", "severidad": "media", "accion_sugerida": "revisar_manualmente"}

api_server.py 
from fastapi import FastAPI, HTTPException
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel
import time

app = FastAPI(title="Motor de Asistencia IA - Hackathon Integrador", version="1.0.0")

# Habilitar CORS para recibir conexiones desde frontends web o Webhooks:
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

class MensajeEntrada(BaseModel):
    mensaje: str
    usuario: str = "invitado"

class RespuestaSalida(BaseModel):
    respuesta: str
    tiempo_ms: float
    ruta_usada: str
    fuentes: list[str] = []

@app.post("/v1/chat", response_model=RespuestaSalida)
async def chatear(entrada: MensajeEntrada):
    inicio = time.perf_counter()
    if not entrada.mensaje.strip():
        raise HTTPException(status_code=400, detail="El mensaje no puede estar vacio.")
    
    tiempo = (time.perf_counter() - inicio) * 1000
    return RespuestaSalida(
        respuesta="Respuesta procesada correctamente mediante el pipeline de IA.",
        tiempo_ms=round(tiempo, 2),
        ruta_usada="RAG_PIPELINE",
        fuentes=["Politica_Devoluciones_Art4"]
    )

22. Resolución Técnica de Bloqueos y Errores Frecuentes

Soluciones directas y verificadas para los 6 problemas más comunes en desarrollo de IA aplicada:

1. ¿Cómo erradicar alucinaciones fácticas en el pipeline RAG? Control Fáctico

Solución: Integre en el System Prompt la directiva: "Responda únicamente a partir de la evidencia del Contexto. Si no está en el Contexto, responda textualmente: 'No cuento con información oficial sobre este tema'." Fije umbral_minimo = 0.40 en rag_engine.py para descartar fragmentos irrelevantes.

2. Error `CUDA Out of memory (OOM)` durante la carga o entrenamiento VRAM Overflow

Solución: Fije per_device_train_batch_size = 1 y active gradient_accumulation_steps = 4. Utilice modelos de escala 1B/3B (ej. Llama-3.2-1B-Instruct) o cuantización NF4 4-bit (QLoRA) para modelos de 8B.

3. Ingesta de archivos locales PDF, Word o CSV en Google Colab Ingesta de Datos

Solución: Suba su archivo en el panel izquierdo de Colab y lea los fragmentos con with open("documento.txt") as f: textos = f.readlines(). Páselos directamente a rag.index_documents(textos).

4. Inspección y prueba interactiva con Swagger UI (`/docs`) OpenAPI Spec

Solución: Inicie el servidor localmente con uvicorn api_server:app --reload --port 8000 y abra http://localhost:8000/docs para enviar payloads JSON de prueba interactivos.

5. Validación estricta de salida en formato JSON Schema Formato Tipado

Solución: Incorpore 2 ejemplos Few-Shot iniciando con { y finalizando con }. Indique en la directiva: "Responda exclusivamente con el bloque JSON parseable, sin introducciones ni marcas Markdown fuera del objeto."

6. Reconexión y persistencia de entorno en Google Colab Sesiones Cloud
