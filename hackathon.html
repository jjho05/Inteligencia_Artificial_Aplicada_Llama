¿Cómo Convertir tu Idea en un Pipeline Funcional de Inteligencia Artificial?

1. El Enfoque Modular Cuatro Capas de Ingeniería para tu Sistema

Cualquier proyecto de IA generativa robusto en el mundo real (sea un asistente médico, asesor legal, bot bancario, recomendador de e-commerce o tutor universitario) se compone de cuatro capas desacopladas. No intentes resolver todo dentro del prompt: asigna a cada módulo su responsabilidad técnica.

Capa 1 Inferencia
1. Enrutador Inteligente (Router)

Tu función: Filtra las consultas del usuario. Envía preguntas triviales al modelo rápido ($< 0.8\text{ s}$) y redirige consultas complejas al motor analítico.

Capa 2 Memoria
2. Base de Conocimiento (RAG)

Tu función: Indexa tus documentos en vectores $\mathbb{R}^{384}$. Recupera los 2-3 fragmentos más similares mediante similitud coseno antes de llamar al LLM.

Capa 3 Especialización
3. Tono & Formato (LoRA / Prompt)

Tu función: Fuerza al modelo a contestar con la personalidad de tu marca y con salida estrictamente estructurada (JSON, Markdown o SQL).

Capa 4 Producción
4. Microservicio API (FastAPI)

Tu función: Empaqueta tu lógica en endpoints HTTP tipados con Pydantic y streaming SSE, listo para ser consumido por WhatsApp o tu frontend.

Bloque A router.py · Enrutador de Complejidad y Model Switching

Evalúa la longitud y palabras clave de la consulta del usuario para decidir si responder al instante con el modelo ligero de Groq o enviar al pipeline RAG/LoRA.

router.py 
import re

class ModelRouter:
    """Clasifica la intencion de la consulta para optimizar latencia y costo."""
    def __init__(self):
        self.palabras_clave_rag = ["politica", "reembolso", "garantia", "manual", "horario", "costo"]
        self.palabras_clave_lora = ["formato json", "esquema", "diagnostico", "codigo"]

    def route(self, consulta: str) -> str:
        texto = consulta.lower()
        
        # 1. Si requiere datos especificos de documentos -> RAG
        if any(k in texto for k in self.palabras_clave_rag):
            return "RAG_PIPELINE"
            
        # 2. Si requiere formato estricto o jerga -> LoRA
        if any(k in texto for k in self.palabras_clave_lora):
            return "LORA_ADAPTER"
            
        # 3. Consultas generales o saludos -> Fast LLM Inferencia Directa
        return "FAST_LLM"

Bloque B rag_engine.py · Motor Vectorial y Búsqueda por Similitud Coseno

Indexa cualquier lista de documentos de texto, calcula incrustaciones densas en $\mathbb{R}^{384}$ y recupera el contexto más relevante aplicando umbral de corte.

rag_engine.py 
import numpy as np
from sentence_transformers import SentenceTransformer

class VectorRAGEngine:
    def __init__(self, model_name="all-MiniLM-L6-v2"):
        self.embedder = SentenceTransformer(model_name)
        self.documentos = []
        self.embeddings = None

    def index_documents(self, docs: list[str]):
        self.documentos = docs
        # Genera vectores y normaliza L2 para que el producto punto equivalga al coseno
        self.embeddings = self.embedder.encode(docs, normalize_embeddings=True)

    def search(self, query: str, top_k=2, threshold=0.40):
        q_emb = self.embedder.encode([query], normalize_embeddings=True)[0]
        scores = np.dot(self.embeddings, q_emb)
        indices = np.argsort(scores)[::-1][:top_k]
        
        resultados = []
        for idx in indices:
            if scores[idx] >= threshold:
                resultados.append({"texto": self.documentos[idx], "score": float(scores[idx])})
        return resultados

Bloque C lora_adapter.py · Inferencia con Adaptadores PEFT

Carga el modelo base y enlaza los pesos adaptados entrenados con LoRA ($W_0 + \frac{\alpha}{r}BA$) para inferencia en GPU o CPU.

lora_adapter.py 
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

class LoRAInferenceEngine:
    def __init__(self, base_model_id="TinyLlama/TinyLlama-1.1B-Chat-v1.0", adapter_path="./lora_checkpoint"):
        self.tokenizer = AutoTokenizer.from_pretrained(base_model_id)
        self.base_model = AutoModelForCausalLM.from_pretrained(
            base_model_id, 
            dtype=torch.float16 if torch.cuda.is_available() else torch.float32,
            device_map="auto"
        )
        # Fusion o enlace de adaptadores de bajo rango
        try:
            self.model = PeftModel.from_pretrained(self.base_model, adapter_path)
        except Exception:
            self.model = self.base_model

    def generate(self, prompt: str, max_new_tokens=80) -> str:
        inputs = self.tokenizer(prompt, return_tensors="pt").to(self.model.device)
        with torch.no_grad():
            outputs = self.model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
        new_tokens = outputs[0][inputs["input_ids"].shape[1]:]
        return self.tokenizer.decode(new_tokens, skip_special_tokens=True).strip()

Bloque D api_server.py · Servidor Web Asíncrono con FastAPI

Expone la arquitectura completa como un microservicio REST tipado con Pydantic y documentación OpenAPI interactiva (`/docs`).

api_server.py 
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import time

app = FastAPI(title="Motor de Asistencia IA Hackathon", version="1.0.0")

class ChatRequest(BaseModel):
    mensaje: str
    usuario_id: str = "usr_demo"

class ChatResponse(BaseModel):
    respuesta: str
    ruta_usada: str
    latencia_ms: float
    fuentes: list[str] = []

@app.post("/v1/chat", response_model=ChatResponse)
async def procesar_mensaje(req: ChatRequest):
    t0 = time.perf_counter()
    if not req.mensaje.strip():
        raise HTTPException(status_code=400, detail="El mensaje no puede estar vacio.")
    
    # Pipeline Integrado: Routing -> RAG -> Generation
    latencia = (time.perf_counter() - t0) * 1000
    return ChatResponse(
        respuesta="Respuesta procesada correctamente con el pipeline de IA.",
        ruta_usada="RAG_PIPELINE",
        latencia_ms=round(latencia, 2),
        fuentes=["Documento_Politicas_Seccion_3"]
    )
Diagnóstico Técnico · Preguntas Frecuentes

Centro de Resolución de Dudas y Errores Comunes

¿Tuviste un error durante la construcción de tu proyecto? Consulta las soluciones directas a los 8 problemas más comunes reportados por desarrolladores de IA:

1. ¿Cómo evitar que mi RAG recupere información basura o fragmentos irrelevantes? Filtro & Chunking

Causa raíz: Chunks demasiado grandes (> 1,000 tokens) diluyen la densidad semántica, o la ausencia de un umbral de similitud obliga al sistema a inyectar siempre los peores fragmentos.

Solución: Divide tu texto en fragmentos de 300 a 500 caracteres con un 15% de overlap. Normaliza los vectores con $L_2$ y aplica un threshold >= 0.42. Si ninguna similitud supera el umbral, indica al LLM que admita que no tiene información en lugar de obligarlo a responder.

2. Error `CUDA Out of memory (OOM)` en Google Colab al cargar el modelo o entrenar Memoria VRAM

Causa raíz: El optimizador AdamW y los tensores de activación superan los 15 GB de la GPU Tesla T4.

Solución: En tu `TrainingArguments`/`SFTConfig`, fija per_device_train_batch_size=1 y activa gradient_accumulation_steps=4. Inyecta LoRA únicamente en target_modules=["q_proj", "v_proj"] y usa torch.float16. Si usas Llama 3.1 8B, cárgalo con QLoRA 4-bit (BitsAndBytesConfig).

3. El modelo no respeta el formato JSON y agrega texto conversacional antes del corchete Prompting & JSON

Causa raíz: Los LLMs son predictores probabilísticos de texto libre y por defecto intentan ser conversacionales.

Solución: Incluye 2 ejemplos Few-Shot en el prompt del sistema mostrando la salida exacta comenzando con { y terminando con }. Si usas la API de Groq, agrega response_format={"type": "json_object"}. En Python, envuelve la decodificación con json.loads() y un validador Pydantic.

4. ¿Cómo conectar mi propio archivo PDF, CSV o TXT al sistema de RAG? Extracción de Datos

Solución: En Python, instala pypdf o pandas. Extrae el texto plano de cada página o fila, divídelo en párrafos semánticos con text.split("\n\n") y pásalo como lista de strings a tu VectorRAGEngine.index_documents(lista_textos).

5. ¿Cómo probar y documentar mis endpoints de FastAPI localmente? Swagger UI

Solución: Inicia tu servidor con uvicorn api_server:app --reload --port 8000. Abre tu navegador en http://localhost:8000/docs para acceder a la interfaz gráfica interactiva de Swagger UI, donde puedes enviar payloads JSON de prueba y ver las respuestas en tiempo real.

6. Error `Rate Limit 429` al hacer llamadas masivas a la API Rate Limiting

Solución: Implementa un decorador de reintentos con Exponential Backoff y Jitter (ej. con la librería tenacity): espera $2^n \times \text{random}(0.5, 1.5)$ segundos antes de reintentar ante excepciones de tipo `RateLimitError`.

7. ¿Cómo combinar RAG y LoRA en una sola respuesta sin duplicar el contexto? Arquitectura Híbrida

Solución: LoRA debe especializarse en el estilo, tono y estructura de salida (aprender cómo responder), mientras que el RAG se encarga de inyectar las citas documentales y hechos (aprender qué responder). El prompt final tiene la forma: Contexto: {rag_chunk}\nPregunta: {user_query}\nRespuesta:.

8. ¿Cómo desplegar mi backend en un endpoint público gratuito para pruebas? Despliegue

Solución: Si estás en Google Colab, usa pyngrok o localtunnel (npx localtunnel --port 8000) para obtener una URL pública HTTPS que puedes conectar a cualquier frontend o webhook de WhatsApp. Para despliegues permanentes, usa Hugging Face Spaces (Gradio/FastAPI) o Render Free Tier.
